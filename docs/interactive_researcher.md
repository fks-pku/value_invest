# 本地交互研究器

研究报告默认打开可编辑版本。先在仓库根目录启动目标项目：

```bash
bash tools/start_researcher.command research/events/meta_muse_cpu_impact_20261009 --port 8765
```

默认打开 <http://127.0.0.1:8765/professional_report.html>；根路径也进入同一编辑器。
页面右上角“导出离线 HTML”提供静态副本。磁盘上的 `professional_report.html`
保留可离线阅读的内容；`file://` 不是默认交付入口，也不能直接启动研究。

交付新报告或重新打开报告时，先启动或复用对应项目的服务，检查 `/api/state`
确实返回目标项目的问题树，再打开可编辑 URL。端口被其它项目占用时另选端口；
不要中断其它项目的研究，也不要把固定端口误当成目标项目。服务不可用时明确说明，
不能把静态预览称为可编辑版。通用启动器必须指定项目目录，不再默认打开 GPT-6 项目。

Muse 项目可双击 `research/events/meta_muse_cpu_impact_20261009/start_researcher.command`。
同一端口只能运行一个项目；切换项目时先结束原服务。编辑器兼容平铺 `nodes` 和嵌套 `root/children` 的 QA 格式，发布时均校验完整问题层级。

## 使用

左侧选中问题，点击“编辑问题”，修改问题与研究要求。确认弹窗列出的重研叶子、父级汇总和移除范围，再点“保存并研究”。

- 修改任一级问题：重研其现有叶子，按层级重新汇总祖先。无关分支不改。
- 新增子问题：支持现有 L2–L4；L3/L4 下钻必须说明具体证据缺口，深度最多 L5。不自动预生成整棵树。
- 移除分支：历史保留；重研原父分支剩余叶子，避免删掉反证却沿用原父结论。不能删根或删空 L1/L2。
- 重新研究：不改问题，重新查材料。失败可重试；取消不会覆盖正式报告。
- 当前版本不支持拖拽重排、新增 L2 主题、后台自动扩树、多用户协作。后续具体缺口在报告中列出，用户确认后再下钻。

研究仍使用项目原有 `as_of_date` 与 `run_mode`，不会自动变成今日实时研究。GPT-6 项目仍是 2026-09-10 截面。

## 实际执行与发布

每个当前叶子使用 `direct-answer-v1`，分两步执行：先在独立、只读的空工作目录
里按原问题检索并形成普通 Codex 式的完整答案，再由整理阶段逐项核读来源、补证并
写入共享报告和账本。第一步只得到题目、截止日、消歧背景和用户补充要求，不带旧答案
或整套报告字段。它不等于证据门禁通过。两步共同使用本轮超时预算；取消在两步均生效。

整理阶段按原题检查信息覆盖，保留内部 `answer_review`；未答部分保留缺口并禁止通过。
程序检查摘录是否确实出现在主文及缺口/状态是否一致，语义完整性仍由 GPT 复核。
原始独立回答保存在本轮本机记录，成功发布后归档到
`research_revisions/<revision>/direct_answers/`，可检查整理是否丢失重要信息。
多问题重研现在会先逐题独立回答，再统一整理，因此可能增加执行时间和用量。

后端调用本机登录的 Codex CLI，启用真实联网检索；没有 mock fallback。根据 [Codex 官方非交互执行文档](https://learn.chatgpt.com/docs/non-interactive-mode)，CLI 可用于自动化执行并复用既有登录。需要可用登录、网络和额度，可能耗时数分钟到一小时。用 `codex login status` 检查登录；应用不读取或保存凭据。

执行器在原 Git 仓库之外的临时目录研究，只有项目副本可写。输入包含动态研究 skill、报告契约和已确认的修改范围；代码、原项目和历史不由模型直接改写。

宿主检查：问题范围/最大深度/无关节点不变、截面锁定、每叶子本轮 search/extraction/review 链、反向检索、执行计划门禁、父子充分性、HTML/MD 共享渲染契约、旧账本只追加、历史版本不改写。检查通过才发布。程序校验不是人类专业复核或全量旧审计通过；语义错误仍可能存在，投资结论不会自动升级为 `actionable_long`。

支持 skill 生成的 `research_state.json` 当前状态投影；发布前校验其版本、节点覆盖、问题、结论、充分性与问题树一致。旧项目可没有这个文件，但存在时必须同步更新。它不能替代追加式证据账本或完成门禁；其它未允许的文件仍拒绝发布。

已验证的问题树同时刷新受影响的 `research_chapters.json` 与视图模型章节缓存；旧章节不能继续显示过期结论或通过状态。公共 HTML/Markdown 始终读取同一问题树。

`progress.json` 仅为临时进度信号，不进入正式研究文件或发布事务。执行器优先读取工作目录根下的进度文件，也兼容写在 `project/` 根下的旧候选。

界面只显示本轮状态和公开研究文章；不向浏览器暴露 CLI 原始日志、凭据、目录内容。服务仅监听 `127.0.0.1`，写操作要求同源及随机 CSRF token；模型输入不拼接进 shell。

状态栏下方的“研究过程”可展开查看本轮公开进展摘要、完成的联网检索次数、最近活动时间，以及逐题检索/抽取/复核记录和来源。默认只看左侧选中的问题，可取消勾选查看全部受影响节点。阶段性结论必须带本轮版本和对应问题，旧答案不会伪装为新进展；未发布草稿与已发布结论分开标注。记录可能分批写入，数量不代表完成百分比或证据通过。只读接口 `/api/process` 不返回命令、工具输出、内部推理、原始查询或本地路径；摘要仅取执行器主动输出的公开工作汇报。研究结束后仍可回看本轮过程。

## 版本与故障

每次确认都会保存 `.researcher/jobs/<revision>/job.json`、`before/`，发布后增加 `after/` 与 `publication.json`。任务状态在重启后可恢复，运行中断标记失败，不会假装续跑。发布中断且未提交时，从 `before/` 回滚。报告可能因证据不足而成功更新为“未充分”，这不同于执行失败。

`.researcher/` 是本机工作区，包含副本和执行记录，不提交 Git。正式研究 artifacts、append-only 账本与研究计划历史仍写回项目并可提交。每次发布还将编辑内容、影响范围和上版问题树写入 `research_revisions/<revision>/`，属于可提交的研究历史。临时路径记录在 job.json 的 workspace；失败候选与诊断日志保留供检查，不公开提供下载。

结束本地服务：启动终端按 Ctrl+C；运行中的研究会收到取消请求。不要同时用其它任务重写项目：发布前内容指纹检查会阻止覆盖外部修改。交互版本发布后，旧 GPT-6 authored-input materializer 会拒绝覆盖；需要重渲染时使用当前问题树与视图模型。
