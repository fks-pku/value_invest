# GPT-6 发布影响：问题框架重新设计

设计日期：2026-09-21。状态：框架设计稿，未切换执行计划，未启动新取证。

本稿按“明确判断 → 提出可能解释 → 设计区分解释的问题 → 取证后修订”重新设计。
旧版 `project.json`、`qa_tree.json`、研究计划、证据账本与 HTML 保持不变。
下列 D 编号仅标识本设计稿，不复用旧问题 ID，也不继承旧节点的结论或通过状态。

## 1. 最终要回答什么

**L1 · D1：GPT-6 的发布，会怎样改变 AI 行业的需求和利润？**

最终答案应说明：相对没有这次发布的路径，哪些客户行为发生变化、净付费改变多少、
何时兑现，以及哪些产业环节和公司的利润因此增加或减少。允许“没有明显变化”与
“现有证据不足以判断”；不预设需求增长、成本下降或算力受益。

沿用当前项目边界：截至 2026-09-10 的可知信息，考察未来 6—24 个月的机制情景；
覆盖模型、应用/Agent、云与 AI 算力，不扩展为全产业链评级或证券买卖建议。
本轮设计日期不是证据截止日。上一轮全网扫描中截止日之后的资料不得倒灌。
事实前提（发布时点、可用产品、访问限制）在启动研究时复核，不单独占据投资问题主干。

## 2. 要区分哪些可能解释

以下均是假说，不是结论；可在不同客户、任务与期间同时成立。

| 可能解释 | 什么观察能帮助区分 |
| --- | --- |
| 技术变化没有显著改变采用行为 | 原有方案已够用，或新增能力被费用、监督、风险和集成门槛抵消；没有持续采用变化。 |
| 发生替代，但行业净付费未明显增加 | 客户迁移模型或软件、缩减旧采购；新产品收入主要来自竞争对手，而非新预算。 |
| 更多工作进入可付费市场 | 新的或更高频的任务被实际采用，并出现持续使用、预算或采购证据；仍需扣除原有支出被替代的部分。 |

即使净付费增加，也可能因降价、服务成本和资本投入而不增利；即使总需求不变，
市场份额、成本与定价变化也可能重新分配利润。因此，不能用需求方向直接替代利润判断。

## 3. 初始问题树：只到 L3

- **L1 · D1：GPT-6 的发布，会怎样改变 AI 行业的需求和利润？**
  - **L2 · D1.1：客户采用 AI 的理由发生了什么变化？**
    - L3 · D1.1.1：哪些重要工作，现在能做得更好或开始做得了？
    - L3 · D1.1.2：同等交付质量下，客户完成工作的总成本怎样变化？
  - **L2 · D1.2：客户对 AI 的净付费需求会怎样变化？**
    - L3 · D1.2.1：发布前，哪些客户已在为什么工作付费？
    - L3 · D1.2.2：发布后，哪些支出是新增，哪些是替代？
    - L3 · D1.2.3：这些支出变化能以多大规模、在何时兑现？
  - **L2 · D1.3：哪些环节和公司的利润会因此改变？**
    - L3 · D1.3.1：需求变化会改变哪些资源采购？
    - L3 · D1.3.2：谁能获得并保留议价权？
    - L3 · D1.3.3：收入与成本的变化，会怎样影响公司利润？

## 4. 为什么这样拆

| 父问题 | 子结论怎样合成父判断 | 哪种相反答案会改变判断 |
| --- | --- | --- |
| D1.1 采用理由 | 能力决定工作能否交付；总成本决定在同质量下是否更划算。两者分开研究，再判断哪些客户有采用或迁移理由。 | 能力无明显提升且经济性不改善，则该类任务缺少新的采用理由；能力不变但更便宜，也可能驱动采用，不能要求两项同时改善。 |
| D1.2 净付费需求 | 先建立当前客户与任务基线，再区分新增、替代及提前支出，最后结合采用证据与约束估计规模和时点。D1.1 只提供采用理由，不证明购买发生。 | 新产品收入若主要替代原有 AI 支出，行业净增量应下调；预算未落实或部署受阻，应推迟兑现。 |
| D1.3 利润归属 | 先看需求对资源采购的传导，再看稀缺性与替代方案决定的议价权，最后将收入、价格、成本和投入落到公司。 | 存量产能足以消化需求、竞争压价或交付成本上升，均可能使销量增长不增利；也允许没有销量增长但降本增利。 |
| D1 行业影响 | 将采用理由、净付费变化、产业利润传导串起来，报告方向、量级、时点和失效条件。 | 不把模型进步、使用量增长或订单增长中的任意一项，单独当成整个行业受益的证明。 |

依赖不等于嵌套：D1.2 引用 D1.1 的任务级判断，D1.3 引用 D1.2 的需求情景；
不在每个分支重新研究同一份能力清单。能力证据也不能直接充当付费或盈利证据。

## 5. 每个 L3 怎样开始研究

先根据 D1.2.1 确定重要的客户—任务组合，再用同一组合贯穿能力、成本、需求和利润研究。
任务选择依据当前支出、使用频率和潜在影响，而不是哪个演示最容易找到。

| 问题 | 需要搜集的数据 | 做什么分析、处理什么反向解释 |
| --- | --- | --- |
| D1.1.1 工作能力 | 同类任务的新旧模型与可采购替代方案实测；验收结果、失败类型、人工介入、工具和权限条件。 | 区分既有任务改善与新可行任务；核对运行环境差异。检验提升是否局限于演示、特殊配置或非关键任务；不能用跑分直接换算生产率。 |
| D1.1.2 客户总成本 | 可比任务的调用账单、执行时间、重试、复核返工、集成投入和错误损失；使用规模与成本摊销。 | 在同质量下比较合格交付总成本，并核对时效。对缺失的人力或风险成本只做标明假设的临界测算；单价或 token 数变化不等于总成本变化。 |
| D1.2.1 当前付费基线 | 截止日前可知的发布前客户构成、任务、付费人数/席位、频率、支出及替代工具；覆盖范围与统计口径。 | 建立客户—任务—支出基线，区分试用与持续付费；缺失规模保留缺口，不拿全行业 TAM 代替。 |
| D1.2.2 新增与替代 | 同客户的预算来源、采购变更、旧工具取消或缩减、任务频率变化、采用原因；发布前趋势和同期竞争变化。 | 判断 AI 行业边界内的净支出变化；区分新增、从其它 AI 产品迁移、从人工/外包预算转移及时间提前。处理总成本下降但任务量上升等相反效应，不把发布后变化全部归因于发布。 |
| D1.2.3 规模与时点 | 可服务客户数、任务频率、净支出、采用率、续用/扩容、预算与合同；上线周期、权限、合规和供给约束。 | 用可比客户群构建有边界的需求情景，检验采购与持续使用是否支持假设；区分兴趣、试点、订单和已实现收入，避免重复客户与重叠预算。 |
| D1.3.1 资源采购 | 分工作负载的任务量、真实资源消耗、模型路由、有效吞吐、现有容量及利用率、合同和新增采购。 | 结合 D1.2 情景判断存量容量能否承接，区分资源使用、租赁支出、新采购和供应商收入。检验效率提升与闲置容量的抵消；不以 token 或 API 价格直接代表物理算力。 |
| D1.3.2 议价权 | 客户可选供应商、切换成本、价格和合同条款、供给扩张周期、差异化资产及竞争者进入。 | 判断哪些环节难以替代以及可维持多久；检验客户自建、多模型路由、平台整合和价格竞争。不能仅凭相关业务敞口认定稀缺。 |
| D1.3.3 公司利润 | 相关分部和客户敞口、增量收入与旧业务蚕食、服务成本、折旧、销售投入、资本开支与回款。 | 将前三组机制落实为公司级盈利情景，并核查自由现金流影响。区分发布造成的变化与原有增长；价格不是厂商成本，收入不是利润，行业结论不能直接套用每家公司。 |

所有新问题均未执行。旧来源可作为候选，但必须重新检查截止日、问题适用性，
并逐题抽取和复核；旧有通过状态不迁移。正式执行仍需建立版本化结构计划与逐 L3 执行契约。

## 6. 先研究哪里，何时修订问题树

**下一执行节点建议：D1.2.1（当前付费基线）。**
先知道哪些客户和工作重要，才有依据选择能力与成本比较样本。随后优先研究这些任务的
D1.1.1、D1.1.2，再验证 D1.2.2 的净支出变化；D1.2.3 与 D1.3 使用上述结果形成情景。
这是初始顺序，不是固定流水线：已有充分证据的部分可复核后跳过，出现能改变总判断的
关键矛盾时优先处理。某一任务没有采用理由，只停止或降级该任务分支，不据此否定整个行业。

每轮先判断为何回答不足，再决定动作：

- 缺一个数据：补证或记录阻塞，不增加层级。
- 当前问题混合多个关键机制：记录具体缺口后展开一层，最多 L5。
- 数据冲突：先核对口径与替代解释，不急于制造子问题。
- 子问题都回答了仍推不出父判断：修订同层问题、合并或调整归属，保留旧版及理由。
- 取决于未来事件：给条件判断与验证指标，不伪造确定答案。

本稿覆盖行业需求与利润机制；**尚不回答证券是否值得买入**。需要证券决策时，再明确
标的、价格与估值截面，并满足稀缺性、盈利弹性、未被定价与风险控制等投资门禁。
不得把该后续阶段当作已经完成，也不在本稿预设一套 L4/L5。

## 7. 设计审查

- 初始仅 L1/L2/L3，共 1 个元问题、3 个父问题、8 个可取证问题。
- 能力与成本分别取证；客户总成本与供应商成本分别归 D1.1.2、D1.3.3。
- 当前基线、净变化、兑现范围分别归 D1.2.1—D1.2.3，不重复计算新增需求。
- 反证嵌入每个问题，不设脱离主判断的通用风险清单。
- 行业需求允许增加、减少或不变；利润允许重新分配而非全链条受益。
- 审查结果：可作为下一版问题设计；不代表新研究已执行或答案充分。

相对旧框架：将“是否已经可用”降为事实前提，将能力从成本下移出，补上付费基线与
新增/替代区分；将算力采购放回利润传导中的资源环节，防止研究一开始就预设硬件受益。
