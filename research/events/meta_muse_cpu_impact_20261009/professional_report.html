它怎样影响 CPU 市场？未充分
Muse主要增加云端执行代码、工具与后台任务的服务器CPU负载，并可能使部分个人任务从终端迁入云端。一亿DAU若按10%有效预留、每人1或2个物理核、每颗128核测算，对应7.81万—15.63万颗容量；按每颗5000—10000美元假设，对应3.91亿—15.63亿美元采购池。实际市场净增尚无专属订单数据，EPYC与Arm路线的份额也未确定。
具体影响哪些公司？未充分
与Muse所需CPU最相关的公司是已有Meta服务器合作的AMD、NVIDIA和Arm，以及提供Graviton云算力的AWS；Intel有Xeon产品和Meta历史合作，但新增份额面临竞争。可验证的是业务入口与产品能力，Muse专属净新增订单及利润分配尚未披露。

综合判断

Muse把个人智能体的代码、工具和后台任务带入云端，扩大服务器CPU的用途，并可能推动部分轻办公任务从本地迁移。产品分支显示已发布与早期用户增长，行业分支显示容量对核时和共享程度高度敏感，公司分支识别AMD、NVIDIA和Arm等业务入口。截至2026年10月9日，尚无可归因的Muse净新增CPU销量或收入；一亿DAU对应十万颗级容量只在明确的预留和核配额假设下成立。

行业增量怎样分配给公司

为什么“每用户2核”不能直接变成采购订单？

第一，任务持续时间不等于 CPU 忙碌时间。一次持续10分钟的任务，可能大部分时间都在等待模型回答、网页加载或用户批准。正确的计算量是各个 CPU 核心实际工作的时间之和，而不是任务从开始到结束的时长。

第二，后台任务会增加 CPU 使用强度。Muse 可在应用关闭后继续执行任务，云端环境支持定时任务。用户数相同时，任务越频繁、实际 CPU 运行越久，所需容量越高；平均核时仍待产品遥测验证。S01S02

第三，内存和服务质量可能比 CPU 算术更早限制服务器密度。沿用样本中的8GB配置，如果100万台虚拟机都全额常驻内存，就对应约8PB内存；即使 CPU 很闲，也不能无限合并到少量服务器。是否休眠、回收内存、共享资源，以及高峰期允许多少等待，会影响实际机器数量。这里的8PB同样只是配额乘法（十进制GB/PB），不是已确认的物理内存部署量。按内存约束算出的服务器数，可能高于只按CPU算出的数量。

第四，所需容量不等于新增采购。Meta 可以使用已有余量，也可能提前扩容；推理服务配套的主机 CPU、共享数据库、网络服务和冗余容量还需另算。上表只估算个人虚拟机执行层，不能代表 Muse 全部基础设施中的 CPU 需求。

所以，截至截止日，能确定的是用户增长会扩大虚拟机执行负载；无法确定的是实际每用户核心小时、峰值并发、全体虚拟机数量和可复用容量，因此也无法给出真实新增 CPU 采购量。百万新增用户既可能对应数百颗，也可能对应数千颗乃至更多 CPU，具体取决于上述条件，而不是由“每人一个云电脑”这句话决定。

由此看，Muse 为服务器 CPU 增加了代理执行这一需求来源；影响规模应看用户增长 × 每用户计算强度，不能把用户人数直接乘以两个物理核心。

由此推断，受益的设计方向是：多核并发、足够的单线程性能、较大的内存容量与带宽、高效虚拟化，以及较低的单位任务能耗。只增加核心数并不够，浏览器、代码执行和存储访问都可能成为瓶颈。Arm 对智能体工作负载的同期说明也将代码执行、服务协调、内存和数据搬运列为 CPU 的主要任务。 Arm 技术文章，2026-09-02

展开观点 2

哪些 CPU 路线受益，哪些面临替代

这里有两种不同的“替代”：

- 同一服务器市场内的替代。当任务可以迁移、总体成本更低时，新一代高密度 CPU 或 Arm 平台可能替代旧服务器。Arm 争夺的是一部分 x86 工作负载和新增份额；与此同时，AMD 的合作说明 x86 也可能继续增长。两者可以同时发生。 - 计算位置的替代。原来由用户电脑运行的一部分浏览器操作、脚本或文件生成工作，可能转到云端 CPU。它改变计算发生的位置，不代表个人电脑的所有用途都消失。

以上是依据架构和合作关系作出的条件性判断。没有足够公开资料量化 Muse 已替代多少颗旧 CPU，或各架构已经获得多少新增份额。

第三，若把“AMD CPU 业务”理解为客户端处理器加 EPYC，比例会低于只比较 EPYC 的结果。以 2025 年为基准，客户端收入为 106.40 亿美元，而 EPYC 收入小于整个数据中心的 166.35 亿美元，因此“客户端＋EPYC”的收入介于 106.40 亿与 272.75 亿美元之间。据这个较宽的边界，10% 情景采购额约相当于其 1.43%—14.69%；该口径不包含嵌入式和游戏主机 SoC，也不是公司披露的独立分部。

最后，采购额要转成 AMD 年度增量收入，还需调整：

年度增量收入 ≈ CPU容量颗数 × 新增采购比例 × AMD供货比例 × 成交均价 ÷ 建设年数

例如，10% 情景若全部新购，但 AMD 只供货一半、分两年均匀交付，则平均年度收入约 0.98亿—3.91 亿美元。这是算例，不是实际供货安排。部署完成后，也不会仅因 DAU 保持 1 亿，就每年重新购买同样数量的 CPU。

由此看，Muse 的确提供了模型推理之外的 CPU 需求来源；1 亿 DAU 可以对应十万颗级、甚至百万颗级的部署，但决定量级的是每用户实际执行负载和资源预留方式。仅凭 DAU 和“2 vCPU”配置，尚不足以认定 AMD 将获得同等规模的新增年度订单。

Muse订单的关键环节

9月20日的单账户Muse记录显示EPYC 9D25及x86_64环境。NVIDIA要承接更多Muse执行负载，需要取得实际部署份额，并完成相应软件镜像与工具适配，在单位任务成本、内存和功耗上满足Meta要求。客户分配、净新增CPU颗数及成交价仍未披露。EA125_STARKS07
