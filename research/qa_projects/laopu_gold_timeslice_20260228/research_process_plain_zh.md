# 老铺黄金回测报告是怎么一步步产生的

这份文档解释 `professional_report.html` 的生成过程。它不是新的投资结论，也不会改变报告本身；它只是把研究流水线用白话讲清楚。

## 1. 先锁定研究任务

用户提出的问题是：按当前研究框架，用回测模式研究老铺黄金的投资机会。

所以第一步不是马上判断“老铺黄金好不好”，而是先把边界锁住：

- 研究对象：老铺黄金，`6181.HK`
- 研究模式：历史回测
- 冻结日：`2026-02-28`
- 报告生成日：`2026-05-30`
- 核心约束：所有研究、推理、评分、排序只能使用 `2026-02-28` 当天及以前已经公开可见的信息
- 唯一允许使用当前时点数据的地方：最终标的表格里的三个月股价变化 label

这意味着，哪怕后来老铺黄金发生了很重要的事情，只要它发生在 `2026-02-28` 之后，就不能用来解释当时为什么应该看好或不看好。

## 2. 再判断这是什么类型的研究

老铺黄金不是一个行业篮子，也不是一个政策事件，而是单公司研究。

所以 Q1-Q4 没有沿用行业研究里的“需求、瓶颈、反证、标的池”原样，而是切成单公司的版本：

- Q1：增长驱动是否真实且可持续
- Q2：公司的价值捕获瓶颈和稀缺性在哪里
- Q3：财务质量、估值赔率和反证风险如何约束分数
- Q4：冻结时点如何形成观察状态

这一步的目的，是避免把所有研究都套成同一张模板。老铺黄金的关键不是“行业有没有空间”，而是“它是否真的拥有高端黄金品牌和顶级渠道的稀缺性，以及市场有没有低估这种稀缺性”。

## 3. 把大问题拆成 QA 树

报告里的 `问题下钻` 就是这棵 QA 树。

完整结构是：

- 4 个 L1 大问题：Q1-Q4
- 8 个 L2 机制问题
- 16 个 L3 叶子问题

L3 是最重要的层级。它不是普通小标题，而是一个个“决策单元”。

每个 L3 都必须回答：

- 这个问题为什么重要
- 它影响哪个评分组件
- 需要什么材料支持
- 什么证据会反驳它
- 应该用哪个专业 skill 处理
- Fact / Inference / Judgment 是否分开

比如 Q3.1.1 问的是“利润增长是否同步转化为经营现金流”。这个问题会直接影响 `evidence_quality` 和 `disconfirming_risk_control`，因为如果利润增长很强但现金流跟不上，系统就不能只看净利润增速给高分。

## 4. 冻结日前可用资料怎么选

这次使用的 thesis sources 都必须在 `2026-02-28` 前可见。

最终进入研究逻辑的资料有五类：

1. `SRC-LPG-2024-RESULTS`
   老铺黄金 2024 年度业绩公告，发布时间 `2025-03-31`

2. `SRC-LPG-2025H1-RESULTS`
   老铺黄金 2025 年中期业绩公告，发布时间 `2025-08-20`

3. `SRC-LPG-CINDA-20250827`
   信达证券 2025H1 更新研报，发布时间 `2025-08-27`

4. `SRC-LPG-CMBC-20251215`
   消费行业估值表，含老铺黄金估值口径，发布时间 `2025-12-15`

5. `SRC-HSI-20260213`
   恒生指数公司 2026 年 2 月指数审议，发布时间 `2026-02-13`

还有一个价格数据源：

- `LBL-6181-PRICE`
  只用于最终 label，不进入研究推理

这点很关键：价格 label 是考试答案，不是做题过程。它只能放在最终表格里衡量预测表现，不能反过来影响 Q1-Q4 和最终排序。

## 5. DeepSeek 具体做了什么

GPT 先定义问题、材料和 schema，然后把每个材料拆成小的 source-parser 任务交给 DeepSeek。

DeepSeek 的角色是资料解析助手，不是投资判断者。

它做的事情包括：

- 从 2024 年报摘出收入、利润、毛利率、分红、增长驱动、审计状态
- 从 2025H1 中报摘出收入、利润、毛利率、现金流、存货、借款、门店、线上成交、高端客群、海外首店、专利/设计资产
- 从券商研报摘出门店数量、高端商场、收入和利润预测、PE、风险提示
- 从估值表摘出价格、收入预测、利润预测、PE、股息率、同业背景
- 从恒生指数审议摘出权重、自由流通因子、生效时间，以及“这是流动性线索，不是基本面证据”

一开始我尝试过把多份材料合成一个大包给 DeepSeek，但 MCP 在工具超时时间内没有返回。后来改成按 source 拆小任务，DeepSeek 可以正常完成。

所以现在报告里的 L3 状态是：

`deepseek_mcp_completed_gpt_verified`

这句话的意思是：DeepSeek 完成了资料抽取，GPT 又对抽取结果做了验证和归一化。

## 6. GPT 负责什么

GPT 不只是把 DeepSeek 的输出搬到报告里。

GPT 负责更上层的判断：

- 设计 Q1-Q4 问题树
- 判断哪些资料能用，哪些资料不能用
- 确认资料是否在冻结日前可见
- 给每个 L3 分配专业 skill
- 检查 DeepSeek 抽取有没有偏离材料
- 把 Fact / Inference / Judgment 分开
- 把 L3 汇总成 L2，再汇总成 L1
- 做最终评分和 action_state
- 确保后验价格不进入推理

简单说，DeepSeek 负责读材料，GPT 负责研究设计、证据审判和最终综合。

## 7. 专业 skill 是怎么用的

这份报告里使用了五类 skill：

- `financial-statement-analysis`
  用于财报、收入、利润、毛利率、现金流、存货、借款、分红等问题

- `industry-report-analysis`
  用于门店、高端商场、品牌稀缺性、产品设计、渠道空间等问题

- `valuation-analysis`
  用于 PE、预测利润、市场是否已经定价、赔率是否足够的问题

- `news-event-analysis`
  用于海外首店、线上事件、指数纳入等事件型线索

- `target-recommendation-analysis`
  用于最终把研究结论映射到 `6181.HK` 的观察状态

每个 L3 卡片里都能看到 Skill、Execution、Score Component 和 Decision Use。

这不是装饰，而是告诉你：这个问题是用哪个专业视角处理的，以及它会影响最终哪个评分维度。

## 8. L3 是怎么变成结论的

每个 L3 都拆成四格：

- Fact：材料里真实披露了什么
- Inference：这些事实说明了什么
- Judgment：这对投资判断有什么影响
- Gap / Trigger：还缺什么，什么情况会改变判断

例子：

Q3.1.1 问“利润增长是否同步转化为经营现金流”。

Fact 是：2025H1 存货、短借上升，经营现金流表面为净流出，剔除部分因素后才转为小幅流入。

Inference 是：公司增长很强，但需要大量黄金原材料备货，利润质量不能简单当作低风险现金流模型。

Judgment 是：这会压低证据质量和风险控制分。

所以它不会因为收入和利润很漂亮就一路推高总分。

## 9. 最终评分怎么形成

最终只有一个观察标的：

`6181.HK 老铺黄金`

它被打了七个核心分：

- `chokepoint_strength`: 4.2
- `future_space`: 4.1
- `valuation_odds`: 3.1
- `evidence_quality`: 3.6
- `disconfirming_risk_control`: 2.8
- `monitorability`: 3.7
- `payoff_convexity`: 3.4

加权后的原始总分是：

`raw_total_score = 3.663`

但系统不是看原始分就结束，还要过稀缺性机会门槛。

老铺黄金通过了两个重要条件：

- 未来需求和增长空间较强
- 品牌和渠道稀缺性较强

但它没有完全通过第三个条件：

- 市场是否仍未充分定价

所以触发了三个 gate reason：

- `market_underpricing_below_gate`
- `valuation_incomplete_before_full_year_results`
- `working_capital_and_gold_price_risk`

因此最终总分被封顶到：

`total_score = 3.49`

最终动作状态是：

`watch_only`

不是 `actionable_long`。

## 10. 为什么不是 actionable_long

白话说，老铺黄金“看起来很好”，但框架要求的是“好，并且还没被市场充分定价，并且风险证据可控”。

截至冻结日，系统看到的是：

- 品牌很强
- 高端商场渠道很稀缺
- 收入和利润增长非常强
- 估值相对成长性不是离谱贵

但同时也看到：

- 2025 全年正式业绩还没披露
- 存货和短期借款上升
- 经营现金流质量还要验证
- 金价波动可能压毛利
- 估值表和指数纳入线索已经让市场看到一部分故事

所以结论不是“看空”，而是“高优先级观察，但等待更硬的数据再升级”。

这也是你新框架最重要的变化：它不会因为一个公司很优秀就自动给高动作状态。

## 11. 三个月 label 是怎么加上的

在 Q1-Q4 和最终 action_state 冻结之后，才附加价格 label。

这次 label 是：

- 起点：`2026-02-27`
- 终点：`2026-05-29`
- 起点收盘价：HKD 723.50
- 终点收盘价：HKD 504.00
- 三个月股价变化：`-30.34%`

这只用于评价预测效果。

它没有参与：

- 资料选择
- Q1-Q4 推理
- 评分
- action_state
- 风险判断

换句话说，报告的研究过程是在“不知道三个月后跌了多少”的情况下完成的。

## 12. 最后做了哪些机器校验

报告生成后跑了三类校验。

第一类：HTML 报告契约校验

结果：

```text
Report contract validation OK: level1=4, level2=8, level3=16
```

它检查：

- 顶层顺序是否是 `当前研究目标 -> 问题下钻 -> 最终标的推荐 -> 来源索引`
- QA 卡片是否可点击折叠
- Q1-Q4 是否完整
- L3 是否存在
- Q4 是否仍在问题下钻里
- label 是否只出现在最终标的推荐区域

第二类：时间截面校验

结果：

```text
Time-slice audit OK: post_cutoff_non_label_count=0, label_only_count=1
```

它检查：

- 是否有冻结日之后的资料混入 thesis
- label 数据是否只用于 final label
- 每个 thesis source 是否有可见日期证明

第三类：研究 artifacts 校验

结果：

```text
Research artifact validation OK: qa_nodes=28, source_extractions=30, targets=1
```

它检查：

- QA 树是否完整
- L3 是否有结构化 source_plan 和 skill_dispatch
- source_extractions 是否填了 schema_fields
- target 是否有七个核心评分和 subcomponents

## 14. 怎么读这份报告

建议阅读顺序是：

1. 先看 `当前研究目标`
   理解冻结日和研究边界。

2. 再看 Q1-Q3
   看增长、稀缺性、财务质量和反证风险是怎么逐层形成的。

3. 重点看 Q4
   Q4 是冻结时点真正形成观察状态的地方。

4. 最后看 `最终标的推荐`
   这里是展示层，会把 Q1-Q4 的判断压缩成一个目标表。

5. 价格 label 只看作考试结果
   它告诉你这次冻结判断后，三个月股价发生了什么，但不要把它倒推回研究逻辑。

## 15. 这份报告最重要的学习点

这份报告其实验证了框架的一个好处：

老铺黄金的基本面故事很强，但框架没有自动给出多头推荐，而是因为估值未充分定价证据、现金流和存货风险，把它压成 `watch_only`。

这符合你现在想要的目标：

不是找“好公司”，而是找“当前还没有被充分定价的巨大机会”。

一个公司可以很优秀，但如果市场已经给了高预期，或者关键风险还没被验证，框架就应该控制分数，而不是强行推荐。
