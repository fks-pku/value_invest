# S 曲线投资研究 Skill

本技能用于模拟专业研究员寻找“下一条可投资 S 曲线”的工作流。核心不是泛泛做行业介绍，而是判断：

1. 一个新技术或新需求是否正在进入大而持久的 S 曲线。
2. 产业链里哪些 BOM / 供应链节点会被这条 S 曲线真实拉动。
3. 哪些节点存在供需缺口、稀缺控制权或不可替代性。
4. 哪些公司能把节点稀缺转成收入、毛利、现金流或估值重估。
5. 市场是否已经充分定价，以及是否仍有赔率。

## 一句话目标

找到未来空间大、趋势接近不可逆、当前处于早期或中早期加速段、且关键供给明显跟不上需求的产业链节点和证券。

## 触发条件

遇到以下任务时使用本技能：

- 研究某个行业、技术、主题、事件的投资机会。
- 用户想寻找“英伟达早期 GPU 供不应求”“存储超级周期”“AI factory”“新技术爆发”这类 S 曲线机会。
- 用户要求按 BOM、产业链、供需关系、未来空间、预期差、标的推荐来研究。
- 用户问“怎么前瞻性发现某一波行情”“怎么知道需求真的大涨”“怎么判断供给跟不上”。
- 用户要求生成或优化 S 曲线投资研究 HTML 报告。

## 研究总原则

- 80% 精力先用于证明或证伪 S 曲线本身：需求是否已经开始加速、未来还有多少空间、何时可能兑现。
- BOM 不是为了堆产业链图，而是为了定位需求会传导到哪些实物/服务/能力节点。
- 每个 BOM 节点独立研究，不把其他节点的机会提前写进当前节点结论。
- 结论必须从来源和 metric 推出来，不能只靠模型常识。
- 如果公开信息能搜到历史数据、公司指引或第三方预期，不要过早写“待补”。只有确实找不到、口径不一致或不可验证时，才标为缺口。
- 回测模式必须防穿越：只有 cutoff date 之前可见的材料能支持研究结论；后验价格表现只能作为标签，不能影响推理。

## 顶层研究流程

### 0. 确认研究设置

先明确：

- 研究主题：行业、技术、事件、公司或资产。
- 研究模式：实时模式或回测模式。
- 回测 cutoff date：只允许使用该日期前可见材料。
- 投资问题：寻找 S 曲线机会、验证某个节点、还是输出标的推荐。
- 证券范围：美股、港股、A 股、全球，或不限制。

### 1. 先判断 S 曲线是否值得研究

先回答四个问题：

| 问题 | 要判断什么 |
|---|---|
| 新技术或新需求是什么？ | 它解决了什么旧约束，为什么现在可能爆发。 |
| 为什么现在是拐点？ | 成本、性能、产品体验、监管、客户预算、基础设施是否同时到位。 |
| 有没有真实需求加速？ | 不能只看主题热度，要看同口径 metric 的历史加速。 |
| 未来还有多大空间？ | 用公司指引、客户指引、第三方预测、财务兑现和第一性原理判断剩余空间与时间。 |

S 曲线判断必须同时包含：

- 历史同口径对比：过去 3 年或若干季度，metric 是否明显加速。
- 当前兑现：需求是否进入收入、订单、backlog、RPO、capex、利用率、价格或毛利。
- 未来预期：公司/客户/第三方是否给出未来指引、TAM、capex、出货、供给规划。
- 第一性原理：为什么未来需求不会被效率提升、替代路线或预算约束抵消。
- 反证：哪些指标会说明 S 曲线不成立或已经过峰。

### 2. 拆 BOM / 技术链

把产业拆成可研究的 BOM / 供应链节点。每个节点必须讲清楚：

- 这个节点是什么。
- 谁提供它。
- 它接受上游什么输入。
- 它自身生产或提供什么。
- 它提供给谁。
- 它的财务验证指标是什么。

公共报告中，先展示 `01 技术链与BOM呈现`，再从 `02` 开始每个 BOM 节点一个大模块。

不要一开始就把竞争格局、瓶颈点、估值全部铺开。第一版聚焦：

- 技术链怎么构成。
- 哪些节点被 S 曲线需求拉动。
- 每个节点六问是否成立。

### 每个 BOM 必须有独立 Playbook

HBM 的研究链不能只作为 HBM 特例。所有 canonical BOM 节点都必须遵守：

`一个 BOM 节点 -> 一个六问 Playbook -> 一个时间证据账本 -> 可重建的研究快照 -> 一个独立报告`

Playbook 固定节点边界、主公式和六问判断模型。每一问可以提供一条简短的节点专属理解思路，但它只是帮助读者入门，不是材料准入清单、强制检索路径或完成门槛。

六问标题可以复用，各节点的基本理解思路应尊重自身机制。但材料解析发现的新变量、新机制和新反证可以直接进入证据账本，不需要先修改逻辑链。

Playbook 不保存来源、日期、事实、结论、缺口和 HTML；这些由本次 research run、证据工件和渲染器分别负责。研究开始前必须校验 BOM registry 与 Playbook registry 的 node ID 一一对应。

## 每个 BOM 节点的六问

每个 BOM 节点都按同一套六问展开：

| 序号 | 问题 | 目的 |
|---|---|---|
| 1 | 当前 BOM 的需求是否会被 S 曲线放大拉动？ | 判断 S 曲线需求是否传导到当前节点，并进一步判断 AI 需求增长 1 倍时，该 BOM 节点需求是否因为单位用量、attach rate、系统规格或价值量提升而增长 0.5 倍、1 倍、2 倍或更高。 |
| 2 | 供给能否跟上？ | 判断有效产能、良率、交期、认证、设备和扩产周期是否慢于需求。 |
| 3 | 谁控制供给？ | 判断控制权在谁手里，是否有份额、资格、生态、IP 或交付壁垒。 |
| 4 | 是否已经财务兑现？ | 判断需求是否进入收入、毛利、订单、backlog、现金流和指引。 |
| 5 | 市场是否已定价？ | 判断增长是否已被估值、盈利预期和股价反应充分计入。 |
| 6 | 反证是什么？ | 定义哪些数据会推翻需求、供给、控制权、财务兑现或赔率。 |

六问完成后，才能对该 BOM 节点做 S 曲线阶段判定。

这里的“完成”是语义门槛，不是卡片已经生成：每问都必须完成当前问题的主动搜索、逐来源解析、来源 ID 和证据摘要；第 6 问还必须保存明确的 `refuting_source_ids` 与 `refutation_evidence_summary`。只有假设性风险清单、不含实际反向证据时，第 6 问仍为未完成，BOM 阶段维持 pending。

标的推荐另有硬门槛。`actionable_long` 必须同时具备 canonical `thesis_node_id`、对应 BOM 六问完成、反证证据完成、公司财务敞口完成、研究截面估值/预期差完成、分项评分证据可追溯，以及包含 metric/threshold/cadence/downgrade action 的 kill tests。任一项缺失均降为 `watch_only`；缺少 BOM 映射则为 `no_action`。必须同时保存候选状态、最终状态和 `research_gate` 原因。

## 每一问的时间研究结构

每个 `BOM 节点 × 六问` 是稳定的逻辑坐标。每份材料拆成原子观点后，映射到 `BOM × 六问 × 时间`。公共报告按以下顺序展示：

1. `基本理解思路`
2. `当前结论`
3. `相较上一截面的变化`
4. `时间演化`
5. `映射材料`
6. `信息覆盖`

### 内部规则 A：基本理解思路

先说明这一问用什么专业模型来判断，不直接跳到结论。

六问对应的默认判断模型：

| 问题 | 判断模型 | 核心用途 |
|---|---|---|
| 需求是否会被 S 曲线放大拉动？ | S 曲线传导与弹性模型 | 判断终端需求是否真实传到当前 BOM，并判断单位用量、attach rate、系统规格或价值量是否放大需求弹性。 |
| 供给能否跟上？ | 产能 / 良率 / 周期 / 认证模型 | 判断有效供给释放速度是否慢于需求斜率。 |
| 谁控制供给？ | 份额 / 壁垒 / 替代 / 客户锁定模型 | 判断稀缺供给是否被少数公司控制，并能否转成利润池。 |
| 是否已经财务兑现？ | 收入 / 毛利 / backlog / 现金流模型 | 判断产业逻辑是否进入报表，而不是停留在叙事或订单新闻。 |
| 市场是否已定价？ | 估值 / 预期差 / 盈利上修模型 | 判断好产业是否仍是好赔率。 |
| 反证是什么？ | 触发器 / 阈值 / 降级动作模型 | 把风险写成可监控的降级纪律。 |

基本理解思路至少说明：

- 模型名称。
- 这一问要判断的核心对象。
- 判断公式或因果框架。
- 核心判别问题。
- 结论规则。

理解思路不得限制信息搜集。任何新材料只要与当前 BOM 和六问有关，都可以拆成原子观点后进入账本。

### 原子观点与时间字段

每条原子观点保存：`published_at`、`effective_period`、`target_period`、`ingested_at`、`material_class`、`ingestion_channel`、来源、类型、立场、实体、指标、映射依据和置信度。事实、预测、观点、消息、估值和反证不得混成一个摘要。

材料先按来源性质细分：

- `official_filing`：官方财报、监管文件、正式业绩公告。
- `official_company`：公司 IR、电话会、投资者日、产品发布。
- `sell_side_research`：证券公司和投行研报。
- `authoritative_third_party`：行业协会、专业数据库和权威咨询机构。
- `market_news`：公开新闻、供应链消息和快讯。
- `expert_opinion`：专家、投资人和行业人士观点。
- `other`：暂时无法可靠归类。

### 双循环搜集

- `question_search`：根据一个 `BOM × 六问` 的覆盖缺口，由 GPT 选择 Universe 和 Exa/AI 搜索任务，只为该问题生成解析任务。
- `knowledge_base_scan`：每天按 canonical BOM query 扫描用户的 IMA 报告库；新报告先按 BOM 路由，再为相关六问分别生成解析任务。

两类材料先进入同一材料入口账本。发现报告不等于形成证据：未解析报告只能进入 BOM inbox，必须经过按问题的 DeepSeek/专业 skill 提取和 GPT 复核，原子观点才进入时间证据账本。无法映射的内容保留在 `unmapped/new_theme`，用于发现此前没有想到的新机制。

### 当前结论与研究修正

新材料不会自动改写结论。只有来源可靠、问题直接、信息新增且足以改变假设时，才生成研究修正记录。没有真实上一快照时，只能标记为基线，不允许用后见之明重建“历史结论”。

## 搜索和材料解析流程

每个最小研究单元都要先搜索再写结论。

### 1. 先定义 source universe

由 GPT 根据当前主题和最小问题决定该搜哪些来源，不让用户手动指定。

来源类型包括：

- 官方材料：财报、10-K/10-Q/20-F、业绩公告、prepared remarks、earnings call、investor day、产品发布、监管文件。
- 专业第三方 universe：例如 SemiAnalysis、Omdia、Dell'Oro、TrendForce、LightCounting、SEMI、Gartner、IDC、Counterpoint、Yole 等，按行业自适应选择。
- 研报和行业报告：卖方、咨询机构、产业数据库。
- 市场消息：新闻、供应链报道、价格/交期/订单消息。
- 观点：专家、投资人、公司访谈、行业会议观点；观点只能提出假设，不能单独提高置信度。

IMA OpenAPI 凭证和原始知识库 ID 不得写入项目。只读取 `IMA_OPENAPI_CLIENTID`、`IMA_OPENAPI_APIKEY` 和 `IMA_KNOWLEDGE_BASE_ID`，持久化状态只保存不可逆引用哈希。回测项目会隔离 cutoff 之后扫描到的材料；每日扫描应写入实时后继项目。

### 2. 再用直接搜索 / Exa 风格搜索

对每个六问问题根据当前覆盖缺口构造直接查询：

- 查询要包含当前 BOM 节点。
- 查询要包含当前六问问题。
- 查询要针对当前缺少的事实、预测、机构观点、估值或反证，不得只使用一个宽泛主题 query。
- 回测模式必须包含 cutoff 限制。
- 查询结果要进入 source pack，公共 HTML 不展示原始查询词。

### 3. 材料解析必须按问题解析

同一份材料可以同时用于多个问题，但每次解析时必须围绕当前问题提取不同字段。

例如同一份 Micron 财报：

- 用于 HBM 空间：提取 HBM TAM、CAGR、客户需求。
- 用于供给：提取价量协议、产能、资格认证。
- 用于财务兑现：提取收入、毛利、指引。
- 用于反证：提取价格、库存、供给释放和管理层风险。

不要因为材料已经被解析过一次，就跳过其他维度。

长材料优先交给 DeepSeek 做第一轮阅读和字段提取；GPT 负责定义问题、验证提取、判断口径和写最终结论。

## 防穿越规则

回测模式下：

- 所有支持研究结论的材料必须在 cutoff date 前可见。
- LLM 先验只能提出假设，不能当作证据。
- 供应链结构、BOM 结论、target ranking、action state 都必须追溯到 cutoff-visible source IDs。
- 后验股价、后验财报、后验新闻只能放在独立 label / evaluation 字段，不能影响报告正文。
- 如果今天的模型知道未来事实，但 cutoff source pack 没有支持，必须写成 gap。

## 标的推荐框架

只有在 S 曲线、BOM 拉动、稀缺控制、财务兑现和定价都被验证后，才输出标的观察列表。

每个标的必须回答：

| 字段 | 内容 |
|---|---|
| 证券 | ticker、公司名、市场。 |
| 对应 BOM 节点 | 它受益于哪个节点，不接受泛主题映射。 |
| 投资假设 | 为什么它能捕获 S 曲线价值。 |
| 胜率 | 需求、供给、控制权、财务兑现的确定性。 |
| 赔率 | 市场是否低估未来增长和盈利弹性。 |
| earnings elasticity | 增量收入如何转成毛利、EPS、FCF 或估值重估。 |
| 风险控制 | 主要反证、监控指标、降级条件。 |
| action state | `actionable_long`、`watch_only` 或 `no_action`。 |

四个核心门槛：

- `scarcity_or_monopoly`
- `mispricing`
- `earnings_elasticity`
- `risk_control`

如果缺少任一门槛，默认 `watch_only` 或 `no_action`。

## 公共 Markdown 呈现契约

公共报告只展示研究结论和可审计证据，不展示执行噪音。

当用户把研究对象明确收窄为一个独立 BOM 时，使用
`report_scope: standalone-bom`，不再套产业链父报告或六问子报告。固定按
`需求侧 -> 供给侧 -> 技术侧 -> 估值侧 -> ESG` 五个视角展示；每个视角只
保留一段 `简单逻辑链`、一张按发布时间由近及远的 `信息时间线`、以及一段
由该时间线推导的 `最新结论与趋势`。时间线必须给材料类型、原文链接和页码/
章节定位，以及只针对当前视角解析出的数据或观点。

顶层顺序：

1. `当前研究的问题`
2. `行业概况`
3. `标的推荐`
4. `来源索引`

行业研究采用父子两级报告：

1. 根目录 `professional_report.md` 是产业链索引：`01 技术链与BOM呈现` + `02 BOM 独立研究目录`。
2. 每个 `boms/<node_id>/professional_report.md` 是一个 BOM 独立研究报告。
3. 同路径 HTML 仅为可选兼容视图，不是研究内容的来源。
4. 根索引只放全链地图、BOM 跳转和综合标的，不再嵌入所有六问全文。
5. 每个子报告只包含一个 BOM，并保留完整六问、时间材料映射、当前结论、历史演化、覆盖状态和 S 曲线汇总。

目录不变量：`一个产业链项目 -> 每个 canonical BOM 一个 boms/<node_id>/ 子项目 -> 一个独立报告`。

每个 BOM 子报告内：

- 节点简介。
- 六问列表。
- 六个问题模块。
- 每个问题模块内部按 `基本理解思路` -> `当前结论` -> `相较上一截面的变化` -> `时间演化` -> `映射材料` -> `信息覆盖` 展示。
- 六问之后再给该 BOM 的 S 曲线阶段判定。

展示规则：

- 嵌套结构默认可折叠。
- 并列层级如果需要卡片，优先一行一个卡片，避免挤成多列难读。
- 密集表格必须支持横向滚动。
- 数据引用放在具体事实旁边，链接标蓝。
- 来源索引默认折叠。
- 不写“本轮更新”“执行计划”“搜索词”“工作台附录”等过程内容，除非用户明确要求看过程。

## 质量检查清单

完成报告前检查：

- 是否真的证明了 S 曲线，而不是只做产业链介绍。
- 是否有同口径历史对比证明“相比以前更多/更快”。
- 是否有未来预期或第一性原理说明“未来还有空间”。
- 02 是否只放实际历史/当前数据。
- 03 是否只放预期/指引/forecast/TAM/target。
- 每个 BOM 节点是否只分析自己，不提前偷渡其他节点结论。
- 每个关键事实是否有来源链接。
- 能搜到的数据是否已经搜齐，不能把可搜数据写成“待补”。
- 缺口是否是真缺口：口径不可得、来源不可见、数据不可验证。
- 回测报告是否没有使用 cutoff 后事实。
- 标的推荐是否同时通过稀缺、错价、盈利弹性和风险控制四门槛。

## 推荐联用技能

- `financial-statement-analysis`：解析财报、分部收入、capex、RPO、backlog、现金流。
- `industry-report-analysis`：解析第三方预测、TAM、供需、价格和市场份额。
- `research-source-planner`：为每个最小问题规划 source universe 和搜索。
- `leaf-research-deepseek`：让 DeepSeek 阅读长材料并做初步字段提取。
- `supply-chain-chokepoint-analysis`：当六问需要进一步判断稀缺和控制权时使用。
- `company-exposure-analysis`：把 BOM 节点映射到公司收入、毛利、订单和现金流。
- `valuation-analysis`：判断市场是否已经定价和赔率。
- `target-ranking-analysis` / `target-recommendation-analysis`：输出最终标的排序和观察列表。
